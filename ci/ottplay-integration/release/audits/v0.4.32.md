# OTTPlay LG 0.4.32 candidate audit

## Device test evidence

The preceding 0.4.31 receiver reported a stopped live stream with
playback_interrupted, pipeline_error 0 and HLS hls_transport_failed without an
outcome. The application remained running. Explicit selection of the same
catalogue channel restored playback. A preceding one-minute capture showed
progress, successful HTTP responses and buffered media; it did not capture the
original interruption and does not establish its cause.

No installation or physical-TV acceptance of this candidate is claimed here.
The published package must be verified and device playback observed separately.

## External compatibility reports known at release time

The observed closed HLS error can represent more than one producer path. Source
review found a concrete loss of a positively captured watchdog deadline. This
candidate addresses that path, not every possible server, network or decoder
failure. Desktop playback success alone does not qualify the native transport.

## Compatibility tiers, and what moved

Receiver and codec compatibility tiers are unchanged. This candidate changes
native transport-failure attribution and explicit restart admission after a live
decoder has been retired. Classic and Modern retain the same playback state. Remote numeric selection also
keeps configured catalogue identity separate from temporary media queues.

## Boundaries

Only evidence captured by the current transport operation may authorize the
existing bounded same-channel retry policy. Abort and exhausted preparation
reserve keep their existing priority. A successful operation, healed seek or new
request cannot inherit an earlier failure classification. Native epoch fences
remain in force, including when a retired worker completes late.

Plaintext body truncation is recorded only for a real peer FIN before the
declared Content-Length, accounting for already copied drain bytes. New requests
clear the evidence and explicit interruption excludes it. Malformed chunk
framing, refused requests and unclassified negative reads do not gain retry
authority. Regression fixtures exercise actual loopback sockets and AVIO reads.

An explicit failed-channel restart grants a fresh catalogue selection through
the normal playback policy, never native decoder or URL authority. Changed
profile, source binding, catalogue, pause, standby, protected settings or newer
viewer selection cannot be overridden by the retained failed-channel receipt.

No blanket retry of unknown failures, cross-source credential reuse, automatic
channel advancement, timeout reduction or new background service is introduced.

Remote numeric playback retains one moved catalogue, rather than cloning it,
only at a successful temporary handoff from a complete durable source. It checks
source/configuration and catalogue ownership again during preparation and at the
matching native admission receipt. Invalid numbers, changed settings, expired
requests and superseded responses cannot publish a replacement catalogue.
An exact streaming encoded-size cap and a separate capacity-based admission
estimate limit retention; neither is a claim about process RSS. Missing proof
fails closed. An active borrowed server playback lease is rejected before
entering ordinary resolution, which would otherwise close that session early.
No second catalogue scan or profile rewrite is used as fallback.

## Qualification

Regression sources exercise the real callback, operation classifier and native
failure publisher, including successful-operation healing and stale sessions.
Restart regressions exercise ordinary selection admission and terminal cleanup,
then verify fresh restart admission and rejection of changed authority.

Frozen-source hosted CI, ARM packaging and original/public artifact verification
must pass before installation. Host regressions do not prove physical receiver
output or sustained recovery. Device observations belong to the exact installed
package and must distinguish recovery from uninterrupted playback.

## Known issues at release, with provenance

The original receiver report lacks the lower-level outcome needed to distinguish
all network failure paths. The positive watchdog defect is independently
demonstrated by source regression coverage; it is not proof that every observed
interruption had that cause. Sustained playback and failure recovery require
device acceptance. Preparation time remains measured separately from playback;
an observed approximately fifteen-second inspection is not a fixed sleep.
