# OTTPlay LG 0.4.21 candidate audit

## Device test evidence

The installed 0.4.19 candidate has repeated user-reported M3U startup failures and freezes. A retained trace also shows one admitted channel with progressing input and position callbacks; that is neither a failing-start trace nor proof that its physical picture moved. No claim is made that every reported failure has one cause.

A bounded-sink regression reproduces a startup deadlock: the actual feed accepts approximately one second, returns BufferFull while the clock is held, and validated queued audio/video already exceed the required acquisition runway. The accepted-only Fresh rule never issues Play. Decoder readiness remains an accepted-media requirement in the correction; current-source queued media covers the separate runway requirement.

A second regression reproduces the case where even the bounded queues are smaller than a sustainable acquisition: 6.3 seconds of real resident media acquired in four seconds, with only 2.7 seconds fitting into the paused pipeline. Startup must also account for real access units retained by that exact loader. This requires contiguous overlap with the queued prefix and a final lease-identity fence; playlist duration and synthetic output-tail metadata are not evidence.

Review found that a minimum/maximum timestamp range could include an internal hole. The correction retains per-packet duration evidence and counts only continuous resident intervals connected to the actual pipeline prefix. Unknown durations do not grant additional resident coverage. The Linux worker also exposed a test that incorrectly required a fixed queued amount after playback had already started earlier; its replacement checks the actual buffering and startup invariants without depending on scheduler order.

A real demux regression uses valid non-independent HLS whose first segment has no IDR and the next has a safe entry. An independent decoder accepts it, whereas the prior external path immediately rejects its first segment. The correction searches only complete, bounded cold-entry acquisitions and does not relax malformed framing or normal discontinuity handling.

The controller retains 89 TV-reported channels and exposes 466 separately labelled US LG Channels catalogue entries. With the native decoder retired, current-channel reads confirmed KTVU-HD 2-1 and ABC News Live 120. The user confirmed ABC News Live picture and sound. This does not qualify every regional entry, native menu navigation or a transparent overlay.

## External compatibility reports known at release time

The user reports that the same channels generally play successfully in Tauri and the browser/server client. This is comparative user evidence, not a controlled device benchmark. The native startup regressions demonstrate two local failure mechanisms independently of that comparison.

## Compatibility tiers, and what moved

The external native access-unit pipeline differs from browser/Tauri engines and from server-prepared Plex media. Codec admission remains deliberately limited; this candidate does not claim universal transport, codec or hardware compatibility. No physical-TV compatibility tier is promoted solely by host tests.

## Release configuration

The 0.4.20 fat-LTO build was stopped before packaging after the owned compiler placed excessive memory pressure on its small worker. No 0.4.20 package was installed. The next local device-validation build uses the existing tvdev profile with the primary application ID and preserved storage. It is explicitly not a stable or shipping-size/performance qualification. Release flags, budgets and CI gates are unchanged.

## Known issues at release, with provenance

Compile and install the exact candidate, then check multiple M3U starts, rapid selection, a long playback interval and recovery on the living-room television. Keep test, package and physical observations separate. Do not auto-advance to a different channel to disguise a failed selection.

The existing queued/accepted timestamp high-water model is retained. Duration-backed continuity in this correction applies to additional producer-resident media; it is not a new continuity ledger for timestamp holes already submitted to the native sink or queues. Gapped-source handling needs separate qualification. The sampled real first channel has continuous 25 fps H.264 and AAC; that observation does not qualify every M3U source.
