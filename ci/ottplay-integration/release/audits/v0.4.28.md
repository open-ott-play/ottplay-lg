contextual category arrows, grouped-settings combined-key handling and missing

have targeted regressions; actual pass results belong to the exact CI run.

## Compatibility tiers, and what moved

The implementation reuses existing category persistence, menu visibility,
parental/kiosk policy, ordinary playback preparation and scene coordination.
Caller receipts and admitted-list metadata are process-local presentation and
continuation proofs, not saved credentials or new playback permission.
Compact shared queue fingerprints avoid retaining full catalogue descriptions.
Settings return remains distinct from direct fullscreen Menu Settings.

Local multiview keeps its existing on-device decoder architecture and resource
limits. New menu navigation and per-window Stop use the existing scene fences
and retirement effects rather than controlling a second playback domain.

## Release configuration

Numeric version 0.4.28 retains com.openottplay.player.native and the OTTPlay title
for in-place updates. The existing main-only beta pipeline must freeze the exact
source plan, pass its full quality gates, build production ARM binaries, verify
package/link provenance and compare published files with the original candidate.
No permissions or persistent profile format are added by this release.

## Known issues at release, with provenance

Physical television layout, Magic Remote behavior, speaker output, thermal
behavior and sustainable decoder count remain device acceptance work. Nine
windows do not guarantee nine HD streams. The existing local backend bounds
software input to 1080p pixels, 8-bit planar YUV420 and a 15 fps presentation
ceiling; initial HLS restrictions and unavailable HLS seeking are unchanged.
Documented unsupported provider-wide language preferences are not aliased to
unrelated transport-specific settings or advertised as implemented.
