# OTTPlay LG 0.4.11 candidate audit

## Current status

Candidate in preparation for installation over the main application on the living-room LG. This iteration addresses the observed live transport failure recovery and native-account Plex command rejection. It is not a public stable qualification.

## Verification

Exact candidate tests and package verification are pending. The preceding interface snapshot passed 4,783 application, 2,275 screen, 1,533 UI and 893 HUD tests. Its three controlled fixtures passed all six renderer-backed replays with zero differences. Those results do not substitute for testing this iteration.

## Device acceptance

No device acceptance is claimed for this candidate yet. The preceding installation preserved the main application ID, profiles and remote registration. Physical Magic Remote sensitivity and sustained playback must be checked separately from host tests.

## Device test evidence

The observed predecessor failure was an admitted live source that stopped after a short interval, with a closed HLS transport-open diagnostic. Its original diagnostic lacked the precise request outcome. The new code preserves known temporary network/server outcomes without interpreting previous successful HTTP counters as evidence for the failed request.

## External compatibility reports known at release time

The viewer reported frozen picture/audio, brief recovery after an explicit resume, then black output. The same native Plex account could play through the interface while the queue command returned a configuration error. These are separate failures; initial pause intent remains unproven by the earlier capture.

## Compatibility tiers, and what moved

No firmware tier changes are asserted. Native-account command preparation uses existing account authorization and an exact active or unique profile; ambiguous, unavailable or revoked sources remain rejected. Explicit imported credentials retain their original source checks.

## Known issues at release, with provenance

Unclassified plaintext transport errors and playlist-fetch errors remain conservative and do not gain automatic retries. Authentication, TLS trust, unsafe requests and unsupported sources are not treated as temporary network failures. The new retry policy does not prove that every previously observed stream failure is repaired. Physical acceptance and exact candidate test results remain pending.

## Release configuration

Application ID remains `com.openottplay.player.native`; package version is `0.4.11`. Main-ID packaging uses `FLAVOR=stable RELEASE=1` to preserve application storage; this naming does not itself qualify a public stable release.
