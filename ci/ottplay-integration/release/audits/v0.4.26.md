# OTTPlay LG 0.4.26 candidate audit

## Device test evidence

The preceding 0.4.25 beta was installed over the established primary application.
The reported startup menu flashes, central loading caption and missing footer
number motivated this change. Physical-TV acceptance of 0.4.26 is not claimed
by source or host checks.

## External compatibility reports known at release time

The central indicator and caption are rendered by our native SDL chrome, not a
firmware video-control overlay. They can use the shared player presentation.

## Compatibility tiers, and what moved

A paint-only startup state follows the normal saved-source restoration owner.
It does not manufacture a Player route, grant playback permission or bypass
parental, source, cancellation or native-session checks. Back retires the
startup request through the existing input-policy owner. Setup, state and
catalogue errors reveal their actual recovery screens. An authenticated native
Home uses the same eligibility checks as its existing saved-provider coordinator,
retaining a source-bound receipt through the queued OTT handoff. User ingress is
fenced before activity/focus stamps only while that covered owner is active;
normal native Plex Home, consent, replay and refused transitions stay visible.

Destination display facts come from the current resolver capture rather than
the filtered browse selection. The footer reuses the real Classic/Modern HUD
composition and clears outgoing technical fields. Known source ordinals remain
visible while transport is pending; ordinals are not persistent media identity.
Hidden list controls and inline preview claims are unavailable beneath cover.

The orbit indicator is an opt-in shared widget variant. Other spinner users
retain their existing styling. Text-entry outlines and hints preserve the
existing keyboard, field classification, masking, draft and Save/Cancel flow.
All shipped locale keys remain complete.

The diagnostic screen census changes with the added presentation state. Older
recordings remain refused. Only the three reviewed controlled anchors that never
instantiate OTT receive a census-header update; segment bytes, initial state
and recorded hashes are unchanged. No production parser exception is added.
