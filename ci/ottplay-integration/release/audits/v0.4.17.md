# OTTPlay LG 0.4.17 candidate audit

## Device test evidence

Local validation passed 1,583 data tests, 896 appkit tests and the full 2,283-screen inventory (the changed census pin was rechecked separately). The final application regression selection passed 408 cases, including initial/pending channel navigation, EPG, numeric ingress, resume, Favorites and recording preflight; both selected screen checks passed. The unchanged full replay gate passed all three fixtures in Targets and Resolve: six runs, original full grades and zero difference counters. Exact ARM packaging and physical television acceptance are separate. The television was turned off by the viewer before installation, so no 0.4.17 physical acceptance is claimed.

## External compatibility reports known at release time

The viewer reported that the second Up did not reveal complete current programme information, restart selected the first channel, and channel switching retained old footer facts and ignored subsequent input during acquisition. Source review additionally confirmed timestamp-dependent M3U channel IDs on the channel-proxy export route.

## Compatibility tiers, and what moved

The shared live metadata projection adopts only an already-admitted source-matched guide. A separate paint-only pending selection supplies the footer, while a ticket/source/list/owner-fenced step capability coalesces only Next/Previous. Pending facts never become decoder authority. Selection changes bypass position-only checkpoint throttling; write failures retain backoff. Timestamp q normalization is limited to the recognised proxy route. Three recordings that never instantiate OTT received the reviewed unused-type census-header migration; payloads, initial hashes, full grades and rejection of prior headers are preserved.

## Known issues at release, with provenance

A same-device selected-manifest header stall was reproduced at the owned proxy: log correlation showed startup readiness waiting for two cached segments, followed by speed-floor aborts. Separate proxy tuning is prepared and held during cluster maintenance. The duplicate extensionless-manifest GET was removed in 0.4.16; no further native timeout, cookie or User-Agent changes are included. Old opaque resume IDs cannot reconstruct their original timestamped URLs; a managed upgrade needs one guarded current-channel handoff. Existing portable Favorites bindings are unchanged.

## Release configuration

Version 0.4.17 uses the existing primary application ID, FLAVOR=stable RELEASE=1, and explicit OTT product configuration. Application identity does not establish public stable qualification.
