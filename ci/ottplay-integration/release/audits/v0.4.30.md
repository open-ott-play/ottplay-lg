receiver capture observed input supply stop while queued video and audio

## Compatibility tiers, and what moved

Only positively identified body transport or deadline failures retain the
existing closed retry reason. Cancellation, byte limits, local I/O, trust,
authentication, malformed data and unsupported media do not borrow it. No
alternate channel, generic container retry, RPC replay or admission bypass is
introduced. Finite-file and existing live retry policies remain separate.

## HTTP context and diagnostics

The external HLS path previously constructed a new transport for each manifest
while segment acquisition used a separate retained transport. The new opt-in
context follows one source through manifest and segment transfers, bounded
cookie state, manual redirects and reconnects. Inspection and playback contexts
remain independent; private opens cannot publish another transfer's abort slot.
Cookie state is never persisted or serialized. Domain-cookie replay requires
public-suffix support; without it, domain-scoped cookies are rejected while
host-only cookies and transport reuse remain available. Malformed cookie state
and resource bounds fail closed.

The passive preparation extension exposes closed producer causes and pending
retry facts without changing legacy status. Callback ages use the producer's
clock; the firmware error number is separate from callback type/index. A final
native sample is captured before matching-session cleanup. Position callbacks
and raw firmware reports remain distinct from actual displayed-frame proof.
The native streaming fixes and legacy capture corrections do not require a
new controller image. The optional preparation action needs a matching server;
its separate deployment remains subject to the existing runtime hold.

## Release configuration
