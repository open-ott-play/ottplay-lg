# OTTPlay LG 0.4.23 candidate

Fence terminal producer errors and transport diagnostics to the native playback
epoch that owns them. A retired HLS or source worker can no longer fail its
replacement session between ownership validation and terminal publication.

Preserve trusted segment-availability and body-transport causes through HLS
failure reporting. Existing bounded recovery can reopen the same selected live
channel. Access refusals, malformed media and unknown error text remain terminal;
this does not authorize switching to another channel.

Expose Search and Add/Remove Favorite directly in the Classic contextual footer,
using the existing guarded actions and measured Browse overflow fallback. Match
the PC client's Classic default on a fresh installation while preserving explicit
saved interface choices. Source protection metadata follows the current provider
classification without inferring protection from a display title.

Add bounded, argument-free remote command ingress evidence to status responses.
This is in-memory diagnostic information, not a persistent actor audit or proof
that a requested playback operation succeeded.

No physical-TV acceptance is claimed for this candidate. Host tests, ARM ABI
checks, compiled package identity and television playback qualification are
separate results. See the current capability inventory for remaining platform
and migration boundaries.

Package SHA-256: `__IPK_SHA256__`.

After downloading release assets into one directory, verify them with
`shasum -a 256 -c ottplay-lg-0.4.23.sha256` before installation.
