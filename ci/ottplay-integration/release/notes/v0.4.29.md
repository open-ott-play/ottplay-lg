# OTTPlay LG 0.4.29 candidate

A transient live HLS playlist failure no longer immediately discards a valid
buffered decoder. Initial, selected and playback manifest requests share their
existing absolute allowance across up to three checked transient attempts.
A valid first request keeps its full allowance.

An exhausted source-preparation timeout or an attributed live disconnect keeps
the exact selected channel. Recovery waits 1, 2, 4, 8, 15 and then 30 seconds
between attempts, capped at 30 seconds while viewer intent and source ownership
remain valid. Sustained native position progress renews the faster allowance.
Finite-file continuation keeps its existing separate failure budget.

Source, profile, list and request changes, Stop, pause and suspend revoke stale
recovery. Each reopening repeats ordinary admission; unknown, authentication,
trust and malformed-media failures are not relabeled as transient networking.
A remote command receives its actual result once, independently of the player's
subsequent source-owned recovery. No retry selects a neighboring channel.

Plain live HLS preserves the logical channel entry through inspection and
acquires a fresh media-session address at native startup, including redirected
entries. Later refreshes retain their accepted media resource and existing
codec/track validation.

The ordinary fullscreen loading orbit is in the top-left corner, matching the
desktop presentation. Non-loading modal status overlays retain their layout.

The application ID and profile storage remain unchanged. Physical-TV behavior
and sustained playback require device acceptance in addition to hosted tests.

Verify with `shasum -a 256 -c ottplay-lg-0.4.29.sha256` before installation.
