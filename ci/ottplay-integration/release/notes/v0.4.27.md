# OTTPlay LG 0.4.27 candidate

Compose PiP, four or nine equal windows, or a central video with up to eight
surrounding windows directly on the television. The default local backend uses
independent software decoders and GLES composition; it does not require a
compositor service. An explicitly paired service remains an optional backend.

Mix authorized M3U, VPortal, Plex and local-file sources from the current
catalogue and captured Favorites. Choose the active window and the single audio
owner with the remote, pointer or existing OTT CLI. The ordinary saved provider
is preserved, and Close can restore the previous source through fresh playback
authorization, including a Favorite from another profile.

Failed windows accept replacement sources. Rapid channel changes keep the latest
target while loading. Pause state is reported consistently, and seekable local
windows advertise both absolute and relative seeking to remote clients. Paused
seeks show one landing frame without resuming; seek epochs and PCM boundaries
prevent stale frames or preroll audio from escaping.

Software inputs are bounded to 1080p pixels and 8-bit planar YUV420, with a 15 fps
presentation ceiling. Nine slots do not promise nine HD streams on every TV.
The source picker retains up to 1152 choices. Initial HLS support excludes
encryption, byte ranges, discontinuities and external-audio groups; HLS seek is
unavailable. Progressive HTTP seeking requires response-declared byte ranges.
Untimed audio packets after a seek are dropped until packet timing is available.
Plex uses direct media. Physical-TV capacity and audio output still require
qualification on the target television.

See [the multiview guide](https://github.com/open-ott-play/ottplay-lg/blob/main/docs/native-multiview.md)
for layouts, per-window sources, audio ownership and CLI examples.

Package SHA-256: `__IPK_SHA256__`.

Verify downloaded release files with
`shasum -a 256 -c ottplay-lg-0.4.27.sha256` before installation.
