# OTTPlay LG 0.4.17 candidate

Reconcile an already-admitted current/next guide with the playing channel even when the transient metadata-completion notice has gone. The current source and confirmed-start checks remain in force. This lets the second Up open current programme information after a cached EPG load.

Save an admitted selection change independently of the ten-second position checkpoint interval. Preserve the current live selection before terminal EOF teardown, so restart can restore it without advancing to another channel.

Channel changes immediately paint the latest selected target in the footer. Repeated channel-rocker input can supersede a pending request, including the first pre-playback load, without granting pending sources decoder authority.

Native M3U channel identity ignores timestamp-shaped `q` only on the recognised channel-proxy route; the current playback URL remains unchanged. Ordinary source selectors and existing Favorites bindings retain their meaning. Older opaque resume IDs cannot be reconstructed safely; a managed upgrade should capture and hand off the current channel once, after which refreshed playlists retain the stable ID.

Authenticated status adds presence/count-only player-information and resume diagnostics. It does not export programme text, source URLs or credentials.

Install over the existing primary application, preserving profiles and registration. Verify checksums with `sha256sum -c ottplay-lg-0.4.17.sha256`.

Package SHA-256: `__IPK_SHA256__`.
