# OTTPlay LG 0.4.21 candidate

Correct external HLS startup and recovery when the native decoder fills before accepting the acquisition runway. Validated media already queued for the current source, and overlapping real access units still owned by its loader, can satisfy the runway; accepted decoder readiness and viewer pause still gate Play. Resident coverage requires actual packet-duration evidence and continuous intervals. Declared playlist duration, timestamp holes or a fabricated tail are not sufficient. Source, seek and retirement fences prevent stale media from authorizing startup.

For non-independent external HLS, search a bounded number of complete segments for a safe cold-entry picture instead of rejecting a valid stream solely because its first available segment starts between keyframes. Invalid framing remains an error. Skipped pictures and audio never enter the decoder or recovery certificate.

Native capture gains closed numeric priming measurements separating decoder-accepted media from queued media. Update the controller and CLI before using the extended capture records. Position callbacks and accepted input counters do not establish physical presentation or lip synchronization.

Retain System television and LG Channels support. A US catalogue and system-player handoff have been checked separately; availability still depends on the television and region.

Physical startup, repeated channel selection and long-running playback of this exact candidate require acceptance on the television. A local `ARM_PROFILE=tvdev` package is functional validation only; it is not a shipping-size, performance or stable-release qualification. The release profile remains unchanged.

Package SHA-256: `__IPK_SHA256__`.

After downloading the release assets into one directory, verify them with `shasum -a 256 -c ottplay-lg-0.4.21.sha256` before installation.
