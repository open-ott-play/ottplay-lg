# OTTPlay LG 0.4.30 candidate

Media inspection retains positively identified HTTP body timeouts and transport
failures after response headers have been accepted. The same checked cause is
preserved while sniffing an extensionless response and while libavformat probes
an already opened media segment. Existing exact-channel live recovery can then
handle those failures instead of stopping on an opaque container error.

Cancellation, the inspection byte limit, trust/authentication refusals and
malformed or unsupported media remain distinct. Generic container errors do
not gain permission to retry. Existing source, profile, selection and admission
ownership checks remain authoritative.

External HLS retains a bounded, memory-only HTTP context across its initial
playlist traversal, segment reads and subsequent refreshes. Inspection and
playback own separate contexts. Private transfers retain their cancellation
ownership when reopened. Cookie import/export and resource failures do not
become transient networking errors.

Native capture reports the firmware error number and computes event ages in
their original monotonic clock domain. A final bounded sample is retained
before the matched failed decoder is stopped. Legacy position-callback fields
retain their format and are not presented as displayed-frame proof.

An opt-in passive preparation diagnostic reports only a closed failure cause
and bounded retry status. The existing preparation status format is unchanged;
older tools retain their current behavior. It starts no media work.

The application ID, profile storage and permissions remain unchanged. Hosted tests and package verification do not replace sustained
physical-TV acceptance.

Package SHA-256: `__IPK_SHA256__`.
Verify with `shasum -a 256 -c ottplay-lg-0.4.30.sha256` before installation.
