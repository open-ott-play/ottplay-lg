# OTTPlay LG 0.4.24 candidate

Keep the native player on its established single-view playback path while adding
System television discovery and handoff for supported LG channels. HLS
startup and recovery stay bound to the selected playback session: a stale
producer cannot fail its replacement, and bounded retry returns to the same
channel instead of advancing automatically.

Classic keeps the compact player controls and existing guarded Search and
Favorite actions. Settings now include an installation-bound multiview service
descriptor whose secret value is redacted from reads and receipts.

Native multiview is an experimental, explicitly configured private-v1
integration. It is disabled unless configured, has no physical-TV acceptance,
and is not qualified for stable release. The normal single-view path remains
the default.

The Runtime/App owner and optional multiview payload now use heap-backed state
instead of deep stack ownership. The path adds no per-frame allocation, and
host fixtures mirror the production ownership model. Settings schema contracts
include the new service setting and retain the order of existing settings.

No physical-TV acceptance is claimed for this candidate. Host tests, ARM ABI
checks, compiled package identity and television playback qualification are
separate results. Do not treat a passing host suite as proof of TV playback or
multiview qualification.

Package SHA-256: `__IPK_SHA256__`.

After downloading release assets into one directory, verify them with
`shasum -a 256 -c ottplay-lg-0.4.24.sha256` before installation.
